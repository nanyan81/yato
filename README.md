# やト：第一块积木

第八块「本机后端」的启动、填写与迁移步骤见 [backend/README.md](backend/README.md)。

当前进度：显示任务、切换完成状态、新增任务，以及第四块的浏览器本地保存练习。还没有服务器数据库。

## 你来填写

打开 `src/my-plan.js`，只修改引号里的介绍、三个任务名称。可以尝试把一项 `completed: false` 改为 `completed: true`，观察进度变化。

## 启动

在此目录打开终端，依次运行：

```powershell
npm install
npm run dev
```

用浏览器打开终端显示的 Local 地址。保持终端运行，修改并保存文件后页面会自动更新。

## 三块之间的关系

- `src/my-plan.js`：你填写的数据。
- `src/main.jsx`：把数据变成页面。
- `src/style.css`：控制页面的颜色和布局。

验收：页面显示你的介绍和三条任务，完成数与配置一致。

## 第二块积木：点击切换状态

打开 `src/task-rules.js`，将 `return completed;` 改为 `return !completed;`。
`!` 表示取反：true 变成 false，false 变成 true。

骨架已经连接好“点击 → 按规则改变状态 → React 更新页面”。留空的规则目前保持原状态，因此填写前点击不会改变勾选。

验收：点击一项未完成任务，勾选和完成数一起变化；再次点击恢复。刷新页面后恢复 `my-plan.js` 的初始数据，本步尚未做持久化。

## 第三块积木：新增任务

在 `src/task-rules.js` 的 `canAddTask` 函数中，把 `return false;` 改为 `return title.length > 0;`。保留第二块已完成的规则。

骨架会先去掉输入的首尾空格，再把名称交给你的规则。返回 true 就新增一条未完成任务，返回 false 就提示并停止。填写前所有添加都会被拒绝，这是本步特意留下的练习。

验收：输入任务后点添加或按 Enter，新任务出现在列表末尾，输入框清空，总数增加；新任务可以勾选；空内容或只有空格的内容不会增加任务。刷新后本次新增仍会消失，后续再做保存。

## 第四块积木：浏览器本地保存

将 `src/task-rules.js` 中的 `saveTasksEnabled = false` 改为 `saveTasksEnabled = true`，保存文件，然后刷新网页以启用。开启前请把需要保留的临时任务记下来，刷新会丢失此前尚未保存的页面状态。

文件关系：`main.jsx` 首次打开时调用 `task-storage.js` 读取存档；有存档就恢复，无存档才使用 `my-plan.js`。任务发生变化后，`useEffect` 调用存储模块写入 `localStorage`。

验收：新增任务并勾选，确认页面提示已保存，刷新后内容与状态仍在；取消勾选后刷新仍为未完成。关闭标签页，再从同一个地址打开也能恢复。

本地数据按网址隔离，包括协议、主机和端口；localhost 与 127.0.0.1 也不同。清除网站数据会删除存档，无痕模式关闭后可能丢失。此阶段只使用一个标签页编辑，不处理多标签页并发合并，也没有跨设备同步、按日期归档。

有存档后修改 `my-plan.js` 不会覆盖存档。读取失败时页面会提示并暂停写入，避免损坏的存档被初始数据覆盖；写入失败也会在页面提示。

## 第五块积木：隐藏入口的管理页面

在当前网址后添加 `/manage`，例如 `http://127.0.0.1:5174/manage`。普通页面没有删除按钮或管理入口。管理页与普通页共享同一份本地存档。`/manage/` 也可访问；请使用正斜杠。

填写 `src/task-rules.js` 中 `shouldKeepTask` 的规则：将函数内的 `return true;` 改为 `return taskId !== deletedId;`。含义是只保留编号与待删除编号不同的任务。填写前会提示完成规则，不会删除。

删除前会弹出确认框，取消不会改变任务。删除后的列表沿用本地保存逻辑；保存成功后，返回首页和刷新都应保持删除结果。可先新增一条临时任务用于验证。最后一条任务删除后显示空列表，刷新也不应恢复示例任务。

这只是通过路径分开界面，没有登录或管理员权限限制；知道地址的人在自己的浏览器中也能打开它。后续接服务器时再按实际需求增加身份与权限校验。生产服务器需要配置 SPA 路由回退，保证直接访问 `/manage` 也能返回 `index.html`。

## 第六块积木：按日期管理

在 `src/task-rules.js` 的 `isTaskOnDate` 中，将 `return false;` 改为 `return taskDate === selectedDate;`。填写前日期列表会为空，这是练习占位；数据没有删除，管理页仍显示全部日期。

任务新增 `date` 字段，格式为 `YYYY-MM-DD`。日期选择只控制显示哪些任务和新任务所属日期；存储模块始终保存完整列表。刷新后默认查看设备本地今天，其他日期通过日期选择器查看。

旧任务没有创建日期，无法推断真实归属，因此首次升级时归到设备本地当天。升级前原始存档会备份到 `yato.tasks.before-dates.v1`，原任务标题、编号与完成状态保持不变。已有日期的任务保持原日期；空列表不会重新生成示例任务。有存档后不会每天自动重复添加示例任务。

验收：填写筛选规则后刷新，原任务在升级当天可见；切换其他日期应为空，添加一条后仅在该日期出现；勾选、刷新、切换日期均保留各自数据。管理页显示日期，删除一个日期的任务不影响其他日期。

## 第七块积木：聊天记录形式的历史侧栏

左侧按今天、昨天、更早、未来计划分组列出有任务的日期，点击后右侧切换清单。每条显示完成数，当前日期高亮，手机窄屏时侧栏放在页面上方并限制列表高度。顶部“今天的计划”只是回到今天，不会复制或清空任务。

`plan-history.js` 将完整列表按日期汇总；`HistorySidebar.jsx` 显示日期按钮；点击调用 `main.jsx` 的 `selectDate`，继续复用上一块的日期筛选规则。分组使用设备本地日期，刷新或操作触发渲染时更新。没有任务的日期不保留历史条目，删除当天最后一项后条目消失。

本块的小练习：把 `src/HistorySidebar.jsx` 顶部的 `historyTitle` 改为自己喜欢的标题。验收：给今天、昨天各加任务，侧栏出现两天，点击切换并勾选后，侧栏完成数同步变化，刷新仍能恢复。
